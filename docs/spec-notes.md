# 追加仕様メモ(設計書に加えて守る決定事項)

- 一般ユーザー画面はスマホ向け(390px、下部タブメニュー + フローティングボタン)。管理者画面(G13〜G16、G18)はPC向け(1280px、ヘッダーメニュー)
- 通報機能: G7の質問・回答から G17(ボトムシート)→ 管理者 G18。同じ投稿への重複通報は不可
- G3(会員登録完了)のあとは自動ログインせず G1 へ戻す
- ★評価はベストアンサーにのみ付ける(決定後は変更不可、質問は解決済みになる)
- スタンプは回答数 10 / 50 / 100 で獲得。回答に添付できるが装飾のみ
- AI即時回答は Google Gemini API(Flash系・無料枠)。質問投稿時に「AI回答希望(use_ai=1)」の場合のみ生成する
- 設計書と食い違う場合は、設計書(docs/design)を正とし、食い違いを報告すること

## 設計との食い違い・設計書にない決定

- G14・G18 の非表示投稿の内容欄: 設計画像は「(不適切な内容のため非表示)」だが、実装は実際の内容に「非表示」バッジを付けて表示する(設計との食い違い)。理由: 管理者が中身を見て公開に戻すかを判断するため
- G7 の通報ボタン: 画像は自分の質問にも通報ボタンが付いているが、02 の⑨「自分の投稿には非表示」を優先して出さない
- AI回答の再試行(G6・G7): キーが空などで失敗する場合は、失敗表示のまま同じ画面に戻る(設計書に記載なし)
- ベストアンサーの回答を削除しても、質問は解決済みのまま(J2)
- 解決済みの質問でも、質問者本人・AI回答希望・AI回答なしの場合は AI回答の再試行ボタンを出す(設計書に記載なし)
- エラー画面: 401・402 はアプリのルートから到達しない既知事項で、Laravel 標準の英語の画面のまま
- 2026-10-03 の追加(G19〜G21・likes テーブル・CRUD の変更)は docs/design の md にだけ反映した。xlsx(01〜03)と画面遷移図.png は未更新(設計との食い違い)。提出物のため、提出前に xlsx と画面遷移図.png の更新が必要
- G19〜G21 には設計画像(Figma)がなく、構成だけを 02 の md に記載した。画像は「設計書の見直し」でまとめて作る

## 企画書との突き合わせで追加した機能(2026-10-03)

企画書の機能一覧のうち、設計書になかった「いいね」「投稿の編集・削除」「ベストアンサー評価の平均」を追加する。画面は G7・G4・G10・G11 の変更と、G19 質問編集・G20 回答編集・G21 削除確認(ボトムシート)の追加。

- いいね(質問・回答)
    - likes テーブル(question_id と answer_id のどちらか一方だけ。同じユーザーが同じ対象に1回まで=ユニーク制約)
    - 通常のフォーム送信(Ajax なし)。POST で付け、DELETE で取り消す(もう一度押すと取り消し)。二重に送っても結果は同じ
    - 同時に2回送られてユニーク制約に当たった場合は、エラーにせず成功として扱う
    - 自分の投稿は 403、非表示の投稿・非表示の質問への回答は 404、利用停止ユーザーは既存のミドルウェアどおり
    - 押した状態は色だけで示さない。heart アイコンの塗りの有無と文言(「いいね済み」など、aria-pressed を含む)で示す。アイコンは <x-icon> に heart を1つ追加し、新しい CSS は増やさない
    - G7 の質問・各回答(ベストアンサーを含む)に件数とボタン。自分の投稿は件数のみ。G4 の質問カードは件数のみ(G11 の一覧には出さない)
    - 件数は利用停止ユーザーが付けたいいねも含めて数える
    - ランキング・スタンプには影響しない
- 質問の編集(G19)
    - 質問者本人のみ(本人以外は 403)。非表示の質問は 404
    - タイトル・カテゴリ・本文だけ変更できる。AI回答希望(use_ai)は変更不可で、G19 には表示しない。AI回答は作り直さない(編集前の本文に対する AI回答がそのまま残る)
    - 「編集済み」の表示は出さない
- 質問の削除(G21)
    - 質問者本人のみ。G21 の確認後、回答・AI回答・通報・いいねを連動削除する(G14 の管理者による削除と同じ)。1つのトランザクションで実行
    - 解決済みの質問・回答が付いた質問も削除できる(制限しない)。副作用: ベストアンサーと★評価も消えるため、回答者の回答数・ランキング・スタンプの獲得状況・評価の平均が下がる
    - 削除後は G4 へ。既に削除された質問を再送信した場合は 404 にせず、G4 に「既に削除されています」
- 回答の編集(G20)・削除(G21)
    - 回答者本人のみ(本人以外は 403)。非表示の回答・非表示の質問への回答は 404
    - ベストアンサーに決定済みの回答は、編集・削除とも不可(G7 に編集・削除ボタンを出さない)
    - 編集できるのは本文だけ。添付スタンプは表示のみで変更不可(回答の削除で回答数が減ると、添付済みのスタンプが未獲得の扱いになり、そのままでは更新できなくなるため)
    - 削除後は G7 へ。既に削除された回答を再送信した場合は 404 にせず、質問が残っていれば G7、質問ごと削除されていれば G4 に「既に削除されています」
- 回答を削除したときの回答数・ランキング・スタンプ
    - 回答数は都度算出するため、回答を削除すると回答数・ランキングはその場で下がる
    - スタンプは現状のロジックのまま(回答数から獲得を判定するため、しきい値を下回ると未獲得に戻る)。既に回答に添付したスタンプは回答に残る
- ベストアンサー評価の平均
    - G11 ①に「ベストアンサー評価の平均」を「★n.n・n件」で表示。0件は「—」
    - G10 ①のランキング一覧に「★n.n」を表示。0件は「—」。G10 ②あなたの順位・G4 ⑨ TOP5 には出さない
    - 対象は回答と質問の両方が公開中のベストアンサー(ランキングの回答数と同じ条件)
    - 小数第1位まで。DB の ROUND は使わず、PHP で合計と件数から計算して round(…, 1)(四捨五入。4.25 → 4.3)
    - 順位の基準は回答数のまま変えない
- 設計書の表記: 既存の画面のヘッダー(バージョン v1.0・更新日付)は変えず、新しい画面・エンティティの作成日付を 2026/10/03 とした
- README の「主な機能」は段階5で更新する

### 実装時に推奨案で決めたこと(設計書に記載なし)

- 評価の平均(段階2)
    - 集計は RankingService の回答数の集計と同じクエリで「評価の合計」「評価の入ったベストアンサーの件数」を取り、平均は RankingEntry で計算する(一覧でも1回のクエリ)
    - 評価が NULL のベストアンサーはアプリでは作られないが、DB では許されるため、平均の対象から除く(ベストアンサー数は従来どおり数える)
    - G11 は統計(質問・回答・BA・順位)の下に「ベストアンサー評価の平均」と値を1行で表示。G10 はランキングの各行の「ベストアンサー n件」の右に「評価 ★n.n」(0件は「評価 —」で★を付けない)。「評価」の文字は、獲得スタンプの「★ 10」と並んだときに区別できるよう付けた(画面で確認して追加)
    - ★の色は既存の .mq-stamp-chip__star(色 #C77700 だけを指定するクラス)を使い、CSS は増やさない
    - 0件の表示は指示どおり「—」(U+2014)。既存の順位なしの「−」(U+2212)とは別の文字

## 見た目の方針(UI リデザイン)

- docs/design の画面画像は、構成・項目・遷移・文言の正として維持する。配色・書体・角丸・影・アイコンはこの方針を優先する(ユーザー承認済み)
- 色は白・薄いグレー・黒が基本で、青は必要な場所だけ。値は resources/sass/_tokens.scss と app.scss の Bootstrap 変数にまとめ、画面ごとの CSS は増やさない
- 文字に使う色は白背景で 4.5:1 以上。ボタン・リンクの青は #0066CC(白文字で 5.57:1)。#007AFF はフォーカスリング・入力中の枠・選択中のアイコン・グラフなど文字以外だけに使う
- Success・Warning・Danger の鮮やかな色は文字に使わない。バッジは薄い背景＋濃い文字(解決済み #1E7A34、未解決・危険 #C4001A、カテゴリ #636366、AI #4B49B8)
- 藍色(#4B49B8 / #F1F1FC)は「AI回答あり」バッジと sparkle アイコンだけに使う
- プレースホルダーは #767676(白で 4.54:1)。#F5F5F7 の上では 4.17:1 になるため、入力欄の背景は白にする
- 入力欄の枠 #D2D2D7 は約 1.5:1 のため、入力中は #007AFF の枠＋リング、エラー時は赤い枠＋警告アイコン＋メッセージで、色以外でも状態が分かるようにする
- 書体はシステムフォント(-apple-system, BlinkMacSystemFont, "Hiragino Sans", "Hiragino Kaku Gothic ProN", "Yu Gothic UI", "Meiryo", "Noto Sans JP", sans-serif)。太さは 400 と 600。Web フォント・CDN・外部画像は使わない
- 角丸は 小 8 / 入力 11 / ボタン 12 / カード 16 / 大 20px。影は最小限で、白い面＋薄い線を基本にする
- アイコンは <x-icon>(インライン SVG・24px の枠・線幅 1.75・currentColor・data-icon 付き)に統一し、絵文字や記号(◆★●🏆🔒 など)をアイコンの代わりに使わない。ただし評価の「★★★★☆」とスタンプの「★ 50回答達成」「★ 10・50・100」は内容を表す文字として残す
- ヘッダーは青い帯を使わず、白(背景ぼかし。非対応のブラウザでは単色の白)＋細い線。下部タブと FAB は safe-area を考慮し、タップ領域は 44px 以上
- 空状態は <x-empty-state>(アイコン＋既存の文言＋補助文)。既存の文言は変えない

### 見た目の最終方針(段階3で確定)

- トークン(resources/sass/_tokens.scss)
    - 色: 背景 #F5F5F7 / 面 #FFFFFF / 本文 #1D1D1F / 補助 #6E6E73 / 枠 #D2D2D7 / 細線 #E5E5EA / 薄いグレーの面 #F2F2F7 / プレースホルダー #767676
    - 青: ボタン・リンク・選択中のラベル #0066CC、文字以外(フォーカスリング・入力中の枠・選択中のアイコン・グラフ) #007AFF、薄い青の面 #EBF3FE
    - 状態の文字色: 解決済み #1E7A34、未解決・危険 #C4001A、ベストアンサー・1位 #A34700(いずれも薄い面と組み合わせて 4.5:1 以上)
    - 角丸 8 / 11 / 12 / 16 / 20px、影は最小限、余白は 4〜32px の段階、文字は 22 / 17 / 15 / 13 / 12px・太さ 400 と 600
- アイコン: すべて <x-icon> のインライン SVG(24px の枠・線幅 1.75・currentColor・data-icon 付き)。絵文字・記号(◆●🏆🔒⚑✓‹›✎)はアイコンに使わない
- 残した記号: 「★」は評価(★★★★☆)・スタンプ名(★ 50回答達成)・ランキングのスタンプ(★ 10・50・100)・マイページの獲得済みスタンプで、内容を表す文字として残す。色は #C77700(文字以外の基準 3:1 以上)
- 選んでいない星(G9)の色は #D2D2D7。選んだかどうかは「評価：n / 5」の文字でも分かる
- AI の色: 藍色(#4B49B8 / #F1F1FC)は「AI回答あり」バッジ・AI 欄見出しの小さな「AI」バッジ・sparkle アイコンだけ。AI 欄の面は薄い青 #F2F6FC、チェックボックスは主色 #0066CC
- ボトムシート・モーダルの背景: 設計画像の濃さ(0.65 相当)から、黒 0.35 に変更(画面の上に重なっても下の内容が読める程度の濃さ)
- 管理者画面: 濃紺のヘッダーをやめ、白＋細い線、選択中のメニューは濃い文字＋#0066CC の下線。構成と操作は変更なし
- グラフ(G13): 線・棒 #007AFF、目盛り #6E6E73(resources/js/app.js の定数2つ)
- エラー画面: 独立した軽いレイアウトのまま、色・書体・角丸だけトークンと同じ値にする
